# Android 设备同步：扫码拷贝对话，并接入远程镜像

## 目标与边界

安卓应用扫电脑上的二维码后，能把电脑上的对话拿到手机上继续。两条路径都要，但它们不是同一件事，不能共用协议、凭据或状态：

1. **拷贝**：把电脑上选中的一条对话下载到手机自己的会话库。之后手机断网也能接着聊，工具调用在手机上执行，访问不了电脑的文件。
2. **镜像**：手机打开电脑已有的远程控制配对链接，成为电脑的一个窗口。对话仍在电脑上跑，工具也在电脑执行。这套协议已在 [移动端远程控制](./mobile-remote-control-cf-workers.md) 与 [多设备远程控制](./remote-control-multi-device.md) 落地，本规范只补安卓入口，不改 Worker、不改配对协议。

不在本规范内：

- 不拷贝工作区文件、记忆、凭据、provider 配置或权限规则。拷贝来的对话里引用的电脑路径在手机上不存在，续聊时按手机工作区重新执行，不回放历史工具调用。
- 不把两条路径合并成一个二维码。拷贝二维码是局域网明文地址加一次性密钥，镜像二维码是 Cloudflare 配对链接，混用会让手机把密钥发到错误的地方。
- 不做双向同步，不做增量续传。拷贝是一次性快照；电脑侧之后的新消息不自动跟到手机。
- 不开放安卓本机服务端到局域网。安卓服务端继续只监听 `127.0.0.1`，见 [独立运行版](./android-standalone.md)。

## 产品规则

- 电脑侧在侧栏 footer 增加「同步到手机」入口，与现有远程控制入口并列，不放进远程控制弹框。弹框列出当前窗口工作区的会话（标题、更新时间），用户勾选一条后才生成二维码。一次只同步一条。
- 二维码内容是 `http://<局域网 IPv4>:<端口>/sync/sessions/<会话 ID>#k=<一次性密钥>`。密钥只进 fragment，不进路径、不进日志。没有可用的非内部 IPv4 地址时不生成二维码，显示原因，不回退到 `127.0.0.1`。
- 二维码 5 分钟内有效，且只接受一次成功拉取。刷新生成新密钥并使旧密钥立即失效。关闭弹框或切换会话即关闭监听。
- 手机在原生首页增加「扫码同步」。扫到拷贝二维码后直连电脑拉取，写入本机会话库，完成后以 `?task=<会话 ID>` 重新加载本机客户端，由既有 `initialTaskId` 引导打开该对话；不新增原生 JS 桥。扫到镜像配对链接则交给 WebView 加载，不在原生层解析 capability。
- 拷贝写入手机当前工作区，标题保留原文并加「来自电脑」前缀，会话 ID 由手机重新分配。同一来源重复拷贝产生新会话，不覆盖旧的。
- 镜像沿用既有双方授权：手机持 capability，电脑用户逐台确认。安卓不记住跨来源的凭据，不绕过桌面确认。

## 状态所有者

| 状态 | 所有者 | 说明 |
| --- | --- | --- |
| 会话正文 | 各端自己的 `~/.lcode/cli/db/db.sqlite` | 电脑与手机各持一份；拷贝是快照，不是共享 |
| 拷贝监听、一次性密钥、截止时间 | 电脑侧 Host 进程内的同步服务 | 不进桌面主进程，不进渲染进程，不持久化 |
| 任务列表行 | 各端自己的 `tasks-index.sqlite` | 手机写入后由既有 `lcodeSessionService` 订阅补行，原生层不写 |
| 镜像配对、设备凭据、桥 | 既有 Worker Room 与桌面 Main | 安卓只是另一个打开配对链接的浏览器 |
| 扫码结果 | 安卓原生层，一次性 | 不缓存，不写入 WebView 的 localStorage |

## 拷贝协议

### 监听

同步服务挂在持有会话库的 Host 进程里。读取复用既有 `session/messages`，不新增协议方法。桌面主进程只经既有 stdio 通道发「开/关」意图，不经手密钥与正文。

- 监听地址 `0.0.0.0`，端口由内核分配。只服务同步路径，不复用 `entry-http`，因此不暴露桌面的会话、文件或 RPC。
- 局域网地址枚举沿用 `scripts/lcode-distribution/runner.mjs` 的 `networkUrls`：只要非 internal 的 IPv4。
- 密钥用 `crypto.randomBytes(32)` 的 base64url，与 `packages/server/src/hostCapability.ts` 同一长度。比对用常量时间。
- 只注册两个路由：`GET /sync/sessions/:id` 返回会话快照，其余路径一律 404。不提供列表接口，会话 ID 由二维码携带，避免局域网内枚举。

### 快照

```text
GET /sync/sessions/<sessionId>
Header: Authorization: Bearer <密钥>
```

- 密钥缺失、不匹配或过期返回 401，且不区分原因。
- 会话不属于开启同步的那个工作区返回 404。工作区以 `workspaceIdentity?.trim() || workspacePath` 判定，与任务索引同一隔离 key。
- 成功返回 `{ title, createdAt, updatedAt, messages }`，`messages` 用既有 `lcodeMessageWithPartsSchema`（`info` + `parts`）。不返回 `session_entry`、用量、权限、input history 或 workflow 行。
- 正文里的绝对路径原样保留，不做改写。它们是历史记录，不是手机上的可执行路径。
- 响应超过 32 MiB 返回 413，不截断。一次成功响应后密钥立即失效，重复拉取返回 401。

### 写入

手机侧由本机服务端接收原生层转发的快照，不让 WebView 直接持有密钥。

- 新增 `commitDeviceSyncBundle`，放在 `apps/lcode-cli/packages/adapters/src/storage/session-store/`，沿用 `commitSharedContextImportBundle` 的 `begin immediate` 事务：会话行、全部 message、全部 part 一次提交，中途失败回滚，不留半条会话。
- 不复用 `importedHistory`。现有两种来源都不是完整消息流：`claudeCode` 只有纯文本，`sharedContext` 只有一段 markdown。
- 会话行的 `directory`、`path`、`project_id`、`workspace_id` 全部按手机当前工作区重写。消息与 part 的 ID 重新分配，`sessionID` 改为新会话。assistant 消息的 `path.cwd` 与 `path.root` 是执行路径，也按手机工作区重写；消息正文、part 文本里出现的绝对路径是历史记录，原样保留。
- 提交成功后走既有 `lcodeSessionService` 的会话订阅，让 `tasks-index.sqlite` 补上这一行。原生层不直接写任务索引。
- 写入失败返回给原生层一个原因，不重试、不部分保留。用户可以再次扫码。

## 镜像入口

安卓不实现镜像协议，只把配对链接送进已有的 Web 客户端。

- `packages/web/src/main.tsx` 的 `MobilePairingGate` 已处理 `/p/<roomId>#c=<capability>`：先双方授权，接受后用 `connectViaWebSocket` 渲染完整 app shell。安卓 WebView 加载该 URL 即复用这条路径。
- 原生层要放行的只有这一类导航：https，路径以 `/p/` 开头。其余外部链接仍交系统浏览器，回环地址规则不变，见 `UrlPolicy`。
- WebView 当前 `MIXED_CONTENT_NEVER_ALLOW`，配对链接是 https，不受影响。不放宽 mixed content。
- 配对页运行在 Worker 域名的 origin 下，与本机 `http://127.0.0.1:31234` 隔离。关闭镜像页回到本机 origin，不共享 localStorage，也不把设备凭据带回本机。
- 桌面确认、capability 轮换、断线恢复都由既有 Main 与 Worker 负责。安卓不新增确认 UI。

## 安卓原生层

- 扫码用 CameraX 取景加 ML Kit 条码识别，只识别 QR。新增 `CAMERA` 权限；拒绝权限时给出说明，不反复弹窗。
- 扫码结果先按前缀分流：`http://<主机>/sync/sessions/` 走拷贝，`https://<主机>/p/<roomId>#c=` 走镜像，其余提示无法识别，不发起连接。
- 拷贝连接只在扫码后发起，超时 15 秒，不重试。明文 http 只允许这一次请求，不加入 `network_security_config` 的全局放行，也不改 `usesCleartextTraffic`。
- 密钥不进日志、不进诊断导出、不进 WebView。拉取由原生层完成，快照经本机回环接口交给服务端写入。
- 首页「扫码同步」与现有「进入」并列。扫码页是独立 Activity，完成后返回，不替换 WebView。

## 失败语义

- 电脑没有可用局域网地址、端口监听失败：不显示二维码，弹框给出原因，不回退到本机地址。
- 密钥过期、已使用、不匹配：手机显示「二维码已失效，请在电脑上刷新」，不暴露是哪一种。
- 快照超过 32 MiB：手机显示体积过大，不写入。
- 写入中途失败：事务回滚，手机会话库不出现该对话。
- 镜像页加载失败、证书错误、Worker 拒绝：回到原生首页并显示原因，不回退到本机客户端冒充已连接。
- 扫码过程中应用被回收：不恢复半次同步，用户重新扫。

## 验收

1. 电脑勾选一条含工具调用的对话，手机扫码后本机会话库出现新会话，消息与 part 数量一致，标题带「来自电脑」，工作区字段全部是手机路径。
2. 同一二维码第二次拉取返回 401；刷新后旧密钥失效、新密钥可用；关闭弹框后端口不再监听。
3. 快照超过 32 MiB 返回 413 且手机无残留；写入过程中断事务回滚，会话列表不出现半条。
4. 无非内部 IPv4 时不生成二维码；密钥不出现在桌面日志、安卓日志与诊断导出中。
5. 手机扫镜像配对链接进入既有配对页，桌面确认后看到电脑当前工作区；拒绝或超时只结束该次请求。关闭镜像页回到本机客户端，本机会话不受影响。
6. 拒绝相机权限后可继续使用本机客户端；无法识别的二维码不发起任何连接。
7. 拷贝来的对话可以在手机上继续发送，工具调用在手机执行；不要求能访问电脑上的原路径。

未在真机上执行的场景不标记为通过。拷贝与镜像分开验证，一条路径通过不等于另一条通过。
